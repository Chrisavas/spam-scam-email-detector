# Model Evaluation & Metrics Report

**Σκοπός:** Αξιολόγηση μοντέλων μηχανικής μάθησης για τον διαχωρισμό Legit και Spam/Scam emails.

## 1. Σύνοψη Δεδομένων (Dataset Overview)
Το μοντέλο εκπαιδεύτηκε και αξιολογήθηκε στο τελικό ενοποιημένο dataset. 
* **Συνολικό μέγεθος:** 13.919 emails
* **Train Set (80%):** 11.135 emails
* **Test Set (20%):** 2.784 emails
* **Κατανομή Κλάσεων:** Έντονο class imbalance, με τα Spam/Scam emails να αποτελούν μόλις το 7.7% του συνόλου (stratified split).

## 2. Σύγκριση Μοντέλων (Model Comparison)

Αξιολογήθηκαν δύο μοντέλα με βάση την απόδοσή τους στο Test Set (2.784 δείγματα). Η αξιολόγηση εστίασε στις μετρικές της κλάσης `Spam`, λόγω της φύσης του προβλήματος.

| Model | ROC-AUC | Spam Recall | Spam Precision | Spam F1-Score | Overall Accuracy |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Baseline (Naive Bayes)** | 0.575 | 0.00 | 0.00 | 0.00 | 0.92 |
| **Main (Random Forest)** | 0.815 | 0.65 | 0.23 | 0.33 | 0.80 |

### 2.1 Baseline Model: Multinomial Naive Bayes
* **Συμπεριφορά:** Το Naive Bayes έπεσε στην παγίδα του class imbalance (majority class trap). Παρόλο που σημείωσε υψηλό Overall Accuracy (92%), αυτό είναι παραπλανητικό, καθώς το μοντέλο προέβλεψε πρακτικά ότι *όλα* τα emails είναι Legit.
* **Αποτέλεσμα:** Δεν κατάφερε να εντοπίσει ούτε ένα Spam email (Recall 0%), καθιστώντας το ακατάλληλο για τον σκοπό του συστήματος.

### 2.2 Main Model: Random Forest
Για την αντιμετώπιση του imbalance, χρησιμοποιήθηκε η παράμετρος `class_weight="balanced"`, η οποία επιβάλλει αυστηρότερη ποινή στα λανθασμένα ταξινομημένα Spam.
* **Συμπεριφορά:** Το μοντέλο απέκτησε ισχυρή ικανότητα διαχωρισμού, όπως φαίνεται από το ROC-AUC (0.815).
* **Εντοπισμός (Recall):** Κατάφερε να εντοπίσει το 65% των πραγματικών Spam emails (138 από τα 213 στο Test Set).
* **Ακρίβεια (Precision):** Το Precision κυμάνθηκε στο 23%. Για να επιτευχθεί υψηλότερο Recall σε τόσο imbalanced δεδομένα, το μοντέλο έγινε πιο ευαίσθητο, αυξάνοντας τα False Positives (475 Legit emails κατηγοριοποιήθηκαν ως Spam).

## 3. Συμπέρασμα και Τελική Επιλογή
Το **Random Forest** επιλέχθηκε ξεκάθαρα ως το τελικό μοντέλο (`classifier.pkl`). Παρά το σχετικά χαμηλό precision, το σύστημά μας στοχεύει στην προληπτική άμυνα (scambaiting). Συνεπώς, είναι προτιμότερο να έχουμε ένα υψηλότερο Spam Recall (0.65), ώστε να αναχαιτίζουμε ικανοποιητικό αριθμό scammers και να τους τροφοδοτούμε στο Generative AI responder.
